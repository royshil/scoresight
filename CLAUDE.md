# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

ScoreSight is a PySide6 (Qt6) desktop app that runs real-time OCR (PaddleOCR's PP-OCRv6 recognizers on onnxruntime by default, or Tesseract) on user-defined boxes over a live video source (camera, NDI, screen capture, URL/RTSP, video file) and pushes the results to outputs (files, a built-in HTTP server, OBS, vMix, UNO, generic HTTP APIs, and TCP/UDP line protocols such as CasparCG's AMCP). Developer docs live in `docs/development/` (architecture, building, testing, translations, releasing).

## Setup and commands

Python **3.13**. Dependencies are pinned exactly in requirements files: `requirements.txt` (runtime, with env markers), `requirements-win.txt` / `requirements-mac.txt` (platform extras), `requirements-build.txt` (PyInstaller, setuptools, pybind11, PyYAML), `requirements-dev.txt` (runtime + pytest, pytest-qt, ruff, pre-commit, PyYAML) and `requirements-tools.txt` (the standalone `scripts/*.py` tools; they need GUI OpenCV, so use a separate venv). `tesserocr` comes from PyPI on macOS/Linux (wheels bundle Tesseract) and from a pinned `simonflueckiger/tesserocr-windows_build` wheel URL on Windows. `onnxruntime` is 1.31.0, and 1.23.2 on macOS x86_64 (the last release with Intel Mac wheels; same predictions).

```sh
uv python install 3.13
uv venv --python 3.13 .venv
# Windows (use .venv/bin/python and requirements-mac.txt on macOS; no platform file on Linux)
uv pip install --python .venv\Scripts\python.exe -r requirements-dev.txt -r requirements-win.txt -r requirements-build.txt
```

- **Windows only:** build the native DirectShow device enumerator (needs MSVC and `requirements-build.txt`): `python src/win32DeviceEnum/setup.py build_ext --inplace`. The `.pyd` is gitignored. Without it, source discovery fails (a warning from source, an error in a frozen build).
- **PP-OCR models:** `python scripts/fetch_models.py` downloads PP-OCRv6 small and tiny (Hugging Face, pinned revisions and SHA-256s, retried, idempotent; `--check` only verifies) into the gitignored `ocr_models/ppocr/<model>/` (`inference.onnx`, `characters.txt`, `config.json`; the folder's `LICENSE` and `NOTICE` are committed). Without them the app runs with Tesseract and the `ppocr` tests skip; the PyInstaller build fails. CI fetches them (cached).
- **Run from source:** `python src/main.py`, from any working directory (`resource_path()` resolves `tesseract/`, `ocr_models/`, `translations/`, `icons/`, `obs_data/` against the repo root). Set `QT_QPA_PLATFORM=offscreen` to run headless.
- **CLI (`src/main.py`):** `--profile NAME` (same as `SCORESIGHT_PROFILE`), `--port N` (HTTP server port, default 18099), `--self-test` (headless: imports every module in `main.SELF_TEST_MODULES`, checks the bundled files, OCRs a synthetic image with each bundled model (the Tesseract ones and every PP-OCR choice, required when frozen), loads the UI and a translation, prints `SELF-TEST OK` and exits 0, else prints the traceback and exits 1). Other arguments go to Qt (e.g. `-platform offscreen`). Ctrl+C, SIGTERM and Ctrl+Break (Windows) close the main window (without File > Ask before closing's question: `close_without_asking`, also set by Update now; `MainWindow.closeConfirmed` never asks offscreen) and run the normal shutdown, which is how to stop a headless (offscreen) instance (the windowed Windows build attaches to its parent's console when offscreen for that: `main.attach_console_for_quit_signals`). A new module in `src/` must be added to `SELF_TEST_MODULES` (`tests/test_app_main.py` checks it).
- **Tests:** `python -m pytest` (config in `pyproject.toml`; `src/` is on the path). Single test: `python -m pytest tests/test_storage.py::test_unsubscribe`. Markers: `ocr` (real Tesseract with the bundled models; auto-skipped if `tesserocr` is missing), `ppocr` (onnxruntime and the PP-OCR models; skipped without them, unless `SCORESIGHT_REQUIRE_PPOCR` is set, which CI does, then the run errors) and `qt` (offscreen Qt widgets), e.g. `-m "not ocr"`. A test that builds a Tesseract `TextDetector` passes its model (`TextDetector(TextDetector.OcrModelIndex.SCOREBOARD_GENERAL)`): with nothing stored it reads with PP-OCR (automatic).
- **Lint/format:** `python -m ruff check .` and `python -m ruff format .` (CI runs `ruff format --check .`). Rules are ruff's defaults (E4/E7/E9/F), no import sorting; `src/ui_*.py` is excluded. `.pre-commit-config.yaml` runs the same ruff version (`pre-commit install`).
- **Compile Qt Designer UI files:** `python scripts/compile_ui.py` turns each `src/*.ui` into `src/ui_*.py` with the venv's `pyside6-uic` (`compile_ui.ps1`/`.sh` are wrappers). `--check` fails if a committed `ui_*.py` is stale. Never hand-edit `ui_*.py`: edit the `.ui` file and recompile.
- **Translations:** after changing user-visible strings (`self.tr()`, `QCoreApplication.translate("Context", ...)` called by name, or `.ui` texts), run `python scripts/update_translations.py`: `pyside6-lupdate` merges the strings of `src/*.py` and `src/*.ui` into `translations/*.ts` (existing translations are kept, new ones are unfinished and show English), then `pyside6-lrelease` compiles the committed `.qm` files. `--qm-only` only compiles; `--check` (run in CI) fails when they are stale. Mark texts that must not be translated (hosts, ports, numbers that are parsed) `notr="true"` in the `.ui`.
- **Build executable:** `pyinstaller --clean --noconfirm scoresight.spec` on any OS (add `-- --debug` for a Windows console build). Output: `dist/scoresight/` (Windows/Linux) or `dist/ScoreSight.app`. Smoke-test it with `python scripts/ci/smoke_test.py dist/scoresight/scoresight.exe` (runs `--self-test` with throw-away settings). The Windows installer is `iscc scoresight.iss` (version from `src/version.py`).
- **End-to-end test and boot time:** `python scripts/ci/e2e_test.py -- python src/main.py` (or `-- dist/scoresight/scoresight.exe`) runs the real app headless (`--profile e2e`, throw-away dirs) on a synthetic scoreboard video and checks that the readings reach `/json`, `/csv`, `/xml`, the files and a mock outbound API, then that it quits with exit code 0 (about 10 s; `--work-dir` keeps its files). `--engine ppocr` (default: a new setup's PP-OCR (automatic); the log must show PP-OCR loaded without a Tesseract fallback) or `--engine tesseract` (General Scoreboard); CI runs both. `python scripts/ci/boot_benchmark.py --runs 5 -- <app command>` measures launch to HTTP-ready (cold/warm) plus the in-app startup phases; `--legacy` for a 0.1.x build (fixed port 18099). Both share `scripts/ci/app_harness.py`.

### Version and environment variables

`src/version.py` (`__version__`) is the single source of truth for the version (window title, About, update check, spec, installer, release workflow). `.env` (gitignored, optional) is loaded at startup and is only needed for `SCORESIGHT_DEBUG`.

| Variable | Purpose |
|---|---|
| `SCORESIGHT_DATA_DIR` | Overrides the settings directory (default `platformdirs.user_data_dir("scoresight")`). |
| `SCORESIGHT_LOG_DIR` | Overrides the log directory (default `platformdirs.user_log_dir("scoresight")`). |
| `SCORESIGHT_PROFILE` | Named profile: settings live in `scoresight-<profile>.json` instead of `scoresight.json`. |
| `SCORESIGHT_DEBUG` | Any value mirrors logs to the console and turns on uvicorn debug and access logging (env or `.env`). |
| `SCORESIGHT_PPOCR_THREADS` | onnxruntime intra-op threads of the PP-OCR engine (default 2; 0 = onnxruntime's default, every core). |
| `SCORESIGHT_STARTUP_REPORT` | A path: once the app is ready, `startup_timing` writes the startup milestones there as JSON (used by the boot benchmark). |

## Architecture

All app code is a flat set of modules in `src/` that import each other by bare module name (`from storage import ...`), not as a package. Running `src/main.py` puts `src/` on `sys.path`. `main.py` parses the CLI and applies the profile **before** importing the app modules, because some of them read settings at import time.

### Frame → OCR → outputs pipeline

1. **Source discovery:** `get_camera_info.py` enumerates devices per OS (DirectShow `.pyd` on Windows, AVFoundation on macOS, `/dev/video*` on Linux, plus NDI via `cyndilib`) into `CameraInfo` objects. `MainWindow` runs it on a worker thread (`mainwindow.run_in_background`, results delivered to the GUI thread by a signal), like the OBS connection and the update check (GitHub Releases API, at startup unless disabled). An installed Windows build (`unins000.exe` beside the exe) offers **Update now** (`app_update.py`, `app_update_ui.py`): it downloads the release's `scoresight-X.Y.Z-windows-x64-setup.exe`, checks it against `SHA256SUMS.txt` and the running exe's Authenticode signer, runs it with `/SILENT /UPDATEREADY=<file> /UPDATEMUTEX=<name> /RELAUNCH=1` and closes when Setup writes the ready file (after the UAC prompt; `scoresight.iss`'s `PrepareToInstall` then waits for the app's mutex, and a `[Run]` entry relaunches it as the user). `scripts/ci/update_test.py <setup.exe>` tests Setup's side (build.yml runs it).
2. **Capture thread:** `source_view.ImageViewer` extends `camera_view.CameraView` (a `QGraphicsView`), which owns a `camera_thread.TimerThread` (a `QThread`, not a Qt child of the view). The thread picks a `BaseVideoCapture` implementation: `OpenCVVideoCaptureWithSettings` (stored Video Settings apply to camera devices; URLs use FFmpeg with 5 s timeouts and RTSP over TCP first, falling back to UDP), `ndi.NDICapture`, `screen_capture_source.ScreenCapture` (mac or Windows/win32gui implementation, or a dummy on Linux), or `phone_camera.PhoneCapture` (the Phone camera source: a phone's browser POSTs JPEG frames to an HTTPS server on the HTTP port + 1, started with the source, with a self-signed certificate and an access key in the page's address, both kept in the data dir; while no phone sends, `read()` returns a waiting picture with the QR code and sets `showing_placeholder`, which `process_frame` previews as it is and never reads). Closing a viewer waits at most `STOP_TIMEOUT_MS` (3 s) for the thread, which otherwise finishes in the background; `camera_thread` keeps running threads alive until they finish. A source failure (`update_error`) raises the main window's source banner with Retry (texts in `source_bar.py`); `CameraView.show_error_text` is only for messages that aren't source failures. The source's state (the dot before the source, the status bar) comes from `status_bar.source_state()` and the thread's `fps`, `nominal_fps`, `retry_count` and last frame time.
3. **Per-frame processing in `TimerThread.process_frame()`:** rotate and crop → optional stabilization (`frame_stabilizer.py`) (`adjust_frame`) → optional four-corner homography (`correct_frame`) → OCR (`run_ocr_cycle`: grayscale → `TextDetector.detect_multi_text(..., color=frame)` on a snapshot of the boxes). OCR runs at the "Detections / s" cadence (0.1/s and up); the preview is emitted about once per second regardless. While the capture runs, the OCR runs on its own thread (`camera_thread.OcrWorker`): `process_frame` hands it a frame only when it is idle, so a slow OCR never stops frames from being read and always reads the latest frame (stale ones are dropped); without a running capture (tests calling `process_frame`) it runs inline. `textDetector.cycle_interval_ms` is set to the time between detections. While new 4-corner points are picked (`ImageViewer.startFourCornerSelection`), `preview_uncorrected` previews the frame without the homography, but the OCR keeps the old correction: it is replaced only on the 4th valid click, and Esc keeps it. Never clear a correction without the user's confirmation.
4. **OCR (`tesseract.py`):** `TextDetector` reads with the chosen engine; both engines' readings go through the same post-filters (`_finish_reading`), so results and states are the same for every output. The OCR model (`ocr_models.py`; stored as `ocr_model`): `"ppocr:auto"` (PP-OCR (automatic), the default when nothing is stored, stored at the first source open if usable), `"ppocr:small"` (accurate), `"ppocr:tiny"` (fast), the Tesseract indexes 0–3 (kept from 0.1/0.2, never rewritten) or a `.traineddata` path; a PP-OCR model that can't be used reads with Tesseract's General Scoreboard (not stored). **PP-OCR** (`ppocr_engine.py`): onnxruntime is imported and the model loaded on a background thread when first chosen (never at startup; boxes are `Empty` until ready; a failed load falls back to Tesseract, logged and shown via `EngineStatus` in the status bar). Each box's colour crop (no Tesseract preprocessing) is batched with the frame's others (one `session.run` per padded width; 48 px high, padded to ≥ 320 px), CTC-decoded with only its `FieldType`'s characters; confidence 0–1 (× 100 against `conf_thresh`). Boxes with almost no contrast are `Empty` (`has_contrast`), skip-similar compares the crop Otsu-thresholded on its own (`similarity_patch`), dot counters use the preprocessed patch with any engine. 2 intra-op threads, no spinning. `AutoChooser` (PP-OCR automatic) switches small → tiny when a frame's batch takes over 70% of `cycle_interval_ms` for 3 s, and back when small would fit in 50% for 10 s; it logs each switch. **Tesseract:** `TextDetector` holds one `tesserocr` API instance; every box's whole Tesseract sequence runs under its lock, and `setOcrModel` swaps models (and the PP-OCR choice) under it. PSM 8 (single word); models in `tesseract/tessdata/*.traineddata`. Each box is read from the part inside the frame, preprocessed on its own copy of the patch (binarization, cleanup, vscale, skew, dilate, invert, autocrop, rescale, W/H normalization, dot counter), with a character whitelist from its `FieldType` (`defaults.CHAR_WHITELISTS`), then post-filtered (format regex, confidence threshold = `conf_thresh` × 100 against the engine's confidence %, smoothing, leading zeros, ordinal suffix). A box skipped by "skip similar image" (its image is like the one of its last accepted read) returns `unchanged_image=True`. `tesserocr` (2.10+) must first be imported on the main thread; keep its import at module level.
5. **Result states (`TimerThread._published_reading`):** `Success`, `FailedFilter`, `Empty`, `SameNoChange`. `target.last_text` is the box's last *good* (Success) reading, and `SameNoChange` always means "same as that": a repeated Success with "update on change", or an unchanged image. A rejected reading never comes back as `SameNoChange`. Outputs treat Success/SameNoChange as good readings; `Empty` is never sent, except through a box's "When blank" (`clear_value`, `_cleared_reading`): a box `Empty` (or, with `blank_or_zero`, zero) for `CLEAR_AFTER_SECONDS` publishes `Success ""` once (its `last_text` becomes `""`, its `last_image` and smoothing are forgotten), then `SameNoChange ""` while it stays blank. Training data samples are snapshotted before `ocr_result_signal` is emitted.
6. **Fan-out (`MainWindow.ocrResult`):**
   - Hold value first: `held_values.HeldValues.apply(results)` returns the results with each held field's replaced by a copy carrying the held value (Success once, then SameNoChange; a held template field isn't evaluated), and makes a released field's next good reading a Success (`finish_released()` does that for template fields, after them). The boxes list records the OCR's own readings; the `TimerThread` is never told. Held values aren't persisted.
   - `template_fields.apply_template_fields(results)` fills `{{Box Name}}` templates from last good readings (Success when the text changed, SameNoChange otherwise, Empty until every referenced box has a good reading).
   - The game (`game_state.GameEngine.update(results)`, then `update_game_state` for `/game` with the other outputs): with a sport chosen (`sports.py`: profiles, and each box's role by its name), it follows the game: a changed value counts once read again, one the sport doesn't allow (a basketball score +5 or going down) once read steadily for 3 s; it emits events (score, period start/end, clock start/stop, fouls, timeouts, final; a lap race (Racing (laps)): lap, final lap, finish, new race, from a Laps To Go / Laps Completed box that may only step one lap the way it counts; a lap board with only some of the next lap's cards turned, e.g. 10 between 20 and 19 (`game_state.half_turned`), counts after `CARD_TURN_HOLD_SECONDS`, 15 s) and keeps the line score. It sees held values (and the readings themselves, not the plausibility holds) and runs while the outputs are paused. **Plausibility holds** (`plausibility_holds.py`, issue #97): before the template fields, `GameEngine.held_back(results)` names the good readings it isn't counting yet (a change the sport doesn't allow, not steady for 3 s; not Hold value or template fields), and `PlausibilityHolds.apply` replaces them with the last good value sent (SameNoChange), makes the next good reading after a hold a Success, and logs each hold (why, then sent or dropped). `game_ui_handler.py` binds the Sport choice (setting `sport`) and the status line, and logs the events.
   - Then every output: `http_server.update_http_server` (FastAPI/uvicorn on `--port`, default **18099**, bound to 0.0.0.0 on a daemon thread; a busy port is logged and the app runs without it; `get_http_server_port()` gives the real port), `api_output.update_out_api`, the vMix and UNO updaters (owned by `vmix_ui_handler`/`uno_ui_handler`), the TCP / UDP output (`tcp_output.TcpOutput`, owned by `tcp_ui_handler`; see below), OBS text sources via `obs_websocket.update_text_source` (per changed good reading, **not** limited by "Save / s"), and `file_output` (txt/csv/xml, flushed at the "Save / s" rate, written only when a value changed, atomically).
   - vMix, UNO, OBS, the outbound API and the TCP / UDP output never block the GUI thread: each sends from an `output_worker.OutputWorker` (one daemon thread per sink, latest value per key, request timeouts, backoff while the endpoint is unreachable, throttled error logging). `main.py` calls `stop_http_server()` and `output_worker.stop_all_workers()` after the event loop.

The viewer draws each box (`resizable_rect.py`) as a cosmetic halo stroke with one fixed-size label pill (`BoxLabel`, `ItemIgnoresTransformations`; HELD with the held value after `ImageViewer.setHeldValues`); `ImageViewer.layoutLabels()` places the pills with `place_label()` so they cover no box or other pill (below, then above, then inside the box), again when the boxes, the zoom or a pill's size change. Keep per-reading work in the overlay cheap: it runs at the detection cadence for every box.

   - The outputs are the rows of the Outputs list (`output_status.DESTINATIONS`, in the order of the pages of `stackedWidget_outputs`; `destinations_view.DestinationsModel` and the status bar's summary show them). `MainWindow.destinationStatuses()` builds each one's `output_status.DestinationStatus` once a second from cheap snapshots (`OutputWorker.status()` and the like), and a row's switch operates the output's own control. A new output adds a key to `DESTINATIONS`, a page and its status function.
   - The TCP / UDP output's page is its own form, `tcp_output.ui`, added as the last page by `tcp_ui_handler.TcpUIHandler`. `tcp_output.TcpOutput` keeps a TCP connection (reconnecting with the worker's backoff, and sending the "on connect" message and every value after each connection), sends UDP datagrams, or, as a TCP server (`TCP_SERVER`), listens on its port (an accept thread, at most `MAX_CLIENTS`) and sends to every connected program, each new one getting the "on connect" message and every value first. It renders the messages from a template (`{field}`, `{value}`, `{json}`, `{xml}` and CasparCG's parameters, escaped per protocol), and a reader thread reads the replies. Its presets (`tcp_output.PRESETS`) are untested with the real products; `docs/tcp-output.md` gives their sources.

`mainwindow.py` is the central hub. It wires the UI, sources, the OBS connection (replaced/closed clients go through `obs_websocket.close_obs_websocket`), configuration import/export, the menus (File, View, Tools, Help, all `QAction`s in the `.ui`; new actions get `menuRole` NoRole so macOS doesn't move e.g. "Setup layout" to Preferences), View > Appearance and Language, and language switching (after `retranslateUi`, `applyRuntimeTexts()` sets the runtime texts again and state the `.ui` defaults would reset is restored, e.g. `vmixUiHandler.restoreUiState()`, `applyLayoutUi()`).

The window is three panes in `splitter_main` (the side panes can be hidden), in two layouts of the same widgets (View > Setup layout / Live layout, `MainWindow.setLayoutMode`, saved as `window_layout`). Setup's widths are saved as `main_splitter_sizes` and restored when Setup is chosen again; Live hides the Inspector, the Adjust picture row and the field footer, keeps its own field list width (`live_fields_width`), draws the readings large (`ReadingDelegate.setDensity`) and shows `listView_liveDestinations` (the same `DestinationsModel`, `CompactDestinationDelegate`). View > Show unused fields hides the fields not on the picture, per layout (`show_unused_fields_setup`/`_live`). Apply a layout's widgets before its pane widths: they set the panes' minimum widths.
- **Fields** (`widget_leftPane`): `tableWidget_boxes` (the Value column is painted by `readings_view.ReadingDelegate`, including a held value's HELD chip and Release button), with Pause outputs and + on top, Place on picture / Remove from picture / Delete field under it, and a context menu and keys (F2, Del, Ctrl+C, Ctrl+H for Hold value) from the `action*Field`/`actionCopyValue`/`actionHoldValue`/`actionReleaseValue`/`actionZoomToBox` actions. Destructive actions ask first (`MainWindow.confirm`).
- **Viewer** (`frame_source_view`): the source bar (the open source, its health dot, Reload, Video settings, the speed; then the view tools, which show icons only when narrow: `source_bar.CompactToolRow`), the Adjust picture row (`widget_viewTools`), the source error, 4-corner and paused banners, and `source_view.ImageViewer` or, with no source, the first-run card (`frame_firstRun`). Its methods are in the "the viewer" section of `mainwindow.py` (`setupViewer`, `applyViewerTexts`, `updateSourceBar`, `updateSourceBanner`, `updateFourCornerUi`, `updateFirstRunCard`...).
- **✨ Auto crop / ✨ Auto layout** (the first buttons of the Adjust picture row, violet with a sparkle: `theme.ai_color`, `ai_button_style`, `tool_icon("sparkle")`): `auto_layout_ui.AutoLayoutUI` takes the capture thread's last frame (`TimerThread.latestRotatedFrame()` for the crop, `latestPicture()` for the boxes), runs `auto_layout` (Qt-free) on a worker thread and calls `MainWindow.applyAutoCrop` (through `cropDrawn`) or `applyAutoLayout` (places Home Score, Away Score, Time and Period; asks before moving placed boxes). The model (`fields_board.onnx`, D-FINE-S, classes home/away/clock/period/other/board) isn't bundled: `auto_layout.download_model` fetches it after asking, from the Hugging Face repo `royshilkrot/scoreboard-layout` at the pinned `MODEL_REVISION` and `MODEL_SHA256`, into `<data dir>/models/`. A result is dropped if the source, rotation, crop or 4-corner correction changed while it ran.
- **Inspector** (`tabWidget_inspector`): the **Box** tab (the selected field's settings in `stackedWidget_boxSettings`, bound by `box_settings_ui_handler.py`, and under them the pinned `groupBox_allBoxes`: the OCR model (PP-OCR items first; each item's data is the stored value; PP-OCR items disabled with a fetch hint when unavailable; PP-OCR (automatic) shows its current model in its item text and tooltip; a one-time non-modal hint when an explicit PP-OCR (accurate) can't keep up), Detections / s and Update on change, wired in `mainwindow.py`; while a PP-OCR model reads, the Box tab's Tesseract Image cleanup rows are disabled with a note, except for a dot counter: `BoxSettingsUIHandler.setPpocr`) and the **Outputs** tab (`destinations_view.py`'s `DestinationsModel`/`DestinationDelegate` in `listView_destinations` over `stackedWidget_outputs`, whose pages are the output settings; the OBS page's `tableView_obsSources`, filled by `obs_ui_handler.OBSSourcesTable`, edits each box's `obs_source_name` through the box storage). `output_status.py` turns the outputs' snapshots (`OutputWorker.status()`, `http_server_stats()`, `FileOutput.status()`, the OBS connection) into a `DestinationStatus` per output once a second; the status bar (`status_bar.py`) shows them too, and a click there opens the output in the Outputs tab.

### Detection boxes and their settings

- `TextDetectionTarget` (in `text_detection_target.py`) subclasses `QRectF` and adds a `name`, a `settings` dict, optional `mini_rects` and runtime OCR state (`last_text`, `last_image`, smoothing and W/H history; not persisted).
- All boxes live in `storage.TextDetectionTargetMemoryStorage`, a singleton `QObject` whose `data_changed` signal drives both the main window's box table and the viewer overlay. `MainWindow` loads the boxes once at startup and saves them 500 ms after any change (and on close).
- The predefined boxes (Home Score, Away Score, Time and others) and their regex presets are in `defaults.py`. Every other name is a "custom" box.
- **To add a per-box setting**, update `defaults.normalize_settings_dict` (the canonical keys and defaults; `getBoxesForStorage` serializes exactly its output, and `tests/test_storage.py` checks that), `box_settings_ui_handler.py` (the UI binding, `settingsWidgets()`, and `IMAGE_CLEANUP_SETTINGS` for an Image cleanup setting) and `tesseract.py`, if the setting affects processing (both engines' post-filters are in `_finish_reading`). If a stored value's meaning changes, bump `storage.BOXES_SCHEMA_VERSION` and extend `storage.migrate_boxes`: boxes are stored with `"boxes_schema_version"` (next to `"boxes"` in the settings file, and in exported files, which are `{"boxes_schema_version": N, "boxes": [...]}`); older ones are migrated once on load (version 2 turned 0.1.x's ineffective `conf_thresh` off).

### Persistence and settings pub/sub

`storage.py` keeps app state in JSON as named documents in `scoresight.json` (or the profile's file) under `storage.get_data_dir()`. Use `store_data`, `fetch_data` and `remove_data`: writes are atomic (temp file + `os.replace`) and serialized by a module lock, and a corrupt file is moved aside as `<name>.corrupt-<timestamp>` instead of being overwritten. `subscribe_to_data(file, key, callback)` registers a callback that runs **after** the write, **synchronously, on whichever thread does the store**; a failing callback is logged and doesn't affect the store. Components that subscribe must call `unsubscribe_from_data(file, key, callback)` when they're torn down. Many components (the capture thread, the video settings, the output modules) read their settings once at construction and then stay current through these subscriptions.

Logging goes through `from sc_logging import logger`. Each session writes `scoresight_<ts>.log` (the app's DEBUG log, shown by the log viewer) and `scoresight_std_<ts>.log` (root logger, INFO) to `sc_logging.get_log_dir()`, keeping the newest 10 of each. If the log files can't be created, logging falls back to stderr and `log_file_path` is `None`. `main.py` creates a `gui_garbage_collector.GuiThreadGarbageCollector` right after the `QApplication`: automatic garbage collection is off and reference cycles are collected from a GUI-thread timer, because a collection triggered on a background thread can finalize Qt objects while the GUI thread uses Qt (a native crash; don't re-enable `gc` in app code). It also calls `sc_logging.enable_crash_traces()` at startup: a native crash (access violation or segfault in Qt, OpenCV, Tesseract...) writes every thread's Python stack (`faulthandler`) to the std log, which the e2e test prints on failure.

Startup is timed by `startup_timing` (imported first in `main.py`; `mark()` from any thread, never raises): once the video sources are discovered (or 5 s after the first event loop pass) it logs one INFO line `Startup: before main.py …, imports …, QApplication …, main window …, show …, first event loop pass …; total …; HTTP server ready at …, video sources discovered at …`. Keep heavy, rarely needed imports out of the startup path (e.g. `screen_capture_source` and `ndi` are imported where they are used).

### Tests

`tests/conftest.py` points `SCORESIGHT_DATA_DIR`/`SCORESIGHT_LOG_DIR` at temp dirs and sets `QT_QPA_PLATFORM=offscreen` before any app module is imported (importing `sc_logging` creates log files), so tests never touch the user's settings. The autouse `data_dir` fixture gives each test its own settings dir and an empty subscriber registry. Other fixtures: `memory_storage`, `make_target`, `make_result`, `text_detector`, `timing` (a reset `startup_timing`), plus pytest-qt's `qapp`/`qtbot`. `tests/test_ci_scripts.py` tests the `scripts/ci` tools (including, with the real OCR, that the e2e boxes read every state of its video). `tests/synthetic_images.py` renders 7-segment and Hershey-font digits for OCR tests. Before constructing `MainWindow`, patch `mainwindow.start_http_server`, `get_http_server_port`, `get_camera_info`, `check_for_updates`, `ImageViewer` and `update_text_source` (see the `patched` fixture in `tests/test_app_mainwindow_smoke.py`). Output tests use a real uvicorn server on a free port (`start_http_server(0)`), not FastAPI's TestClient.

### OCR evaluation (`ocr_eval/`)

`ocr_eval/` (a package at the repo root, run from there as `python -m ocr_eval list|run|compare|report|validate|review|import-dojo|requirements`; not part of the app) measures OCR engines on datasets of real crops against committed baselines; see `docs/development/ocr-eval.md`. The decision report is `ocr_eval/results/2026-10-11/REPORT.md` (on the 2,040 real crops a user would box, PP-OCRv6 `small` with the whitelist decoder reads 95.1% exactly, `tiny` 90.0%, Tesseract tuned on the dev split 56.8%, the app's default 31.2%; it recommends `tiny` as the default until `small` is measured on a laptop-class CPU, and OCR off the capture thread); its tables are recomputed from that folder's results files by `tables.py` there, with intervals and paired tests that resample photos (`metrics.cluster_bootstrap_interval`, `cluster_sign_flip_p`; a crop's photo is `Sample.cluster`: its `group`, `source_image` or `frame`).

- **Datasets** are folders with `manifest.jsonl` (one raw, never binarized, crop per row: `text`, `field_type`, `display_tech`, `split`, `label_source`, license and attribution), `LICENSE` and `ATTRIBUTION.md`. Committed: `ocr_eval/datasets/textocr_scoreboards` (1,276 real crops, CC BY, TextOCR's human transcriptions; rebuilt by `ocr_eval/builders/textocr_scoreboards.py` plus its review JSON), `commons_scoreboards` (1,044 fields of 186 Wikimedia Commons photos, CC BY/BY-SA/CC0/PD per photo, labels model-assisted and not yet checked by a person; rebuilt by `ocr_eval/builders/commons_scoreboards.py` from its labels JSON, checked with `python -m ocr_eval review` and `--apply-review`) and `synthetic_7seg` (a control). Only redistributable licenses may be committed (`validate --strict-licenses`).
- **Engines** are modules in `ocr_eval/engines/`, discovered automatically (any `Engine` subclass with a `name`; module-level `REQUIREMENTS`; optional deps imported only in `load()`): `tesseract_scoresight.py` (the real `tesseract.TextDetector` with each field type's `defaults.py` box settings, or the preset of a Commons crop's role (`fields.ROLE_BOXES`); the 8 untuned presets plus `tuned`, whose settings `results/2026-10-11/tune_tesseract.py` chose on the dev split; the character whitelists live in `defaults.py` so the harness can apply ScoreSight's post-filter without Tesseract), `ppocr.py` (PP-OCRv6/v5 recognizers on onnxruntime, models pinned to Hugging Face revisions), `ppocr_scoresight.py` (`ppocr-app`: the app's own PP-OCR engine through `TextDetector`, a batch of crops read as one frame's boxes; its predictions equal `ppocr:v6-small-wl`/`v6-tiny-wl` on every crop), `onnxtr.py` (docTR's PARSeq, ViTSTR, CRNN, VIPTR), `windows_ocr.py` and `apple_vision.py` (the OS OCR; shared preprocessing in `_os_ocr.py`, which the leading underscore keeps out of discovery; `windows_ocr` loads System32's `msvcp140.dll` before pywinrt, whose old copy crashes tesserocr; Apple Vision has never run on a Mac) and `vlm.py` (Florence-2, SmolVLM, Qwen; the VLM evaluation was stopped: too slow on a CPU). `-wl` variants limit decoding to the field type's whitelist; `-bin` ones read ScoreSight's binarized patch (much worse for every neural engine).
- **Extras** go in a separate venv: `requirements-eval.txt` pins every adapter's `REQUIREMENTS` by engine (`tests/test_ocr_eval_requirements.py` keeps them in sync; the VLM pins are commented out). onnxruntime ≥ 1.24 has no macOS x86_64 wheels.
- **Results files**: `read_results()` reads plain or gzipped JSON. CI baselines stay plain JSON (`ocr_eval/baselines/tesseract.json`, `tesseract-commons.json`, `ppocr-ci.json`, `ppocr-app-ci.json`, which a test keeps equal to `ppocr-ci.json` crop for crop); reference runs CI doesn't compare are `.json.gz` (`baselines/ppocr`, `onnxtr`, `windows-ocr`, `vlm/*`). `latency.cpu_ms` is the process CPU time per crop. `compare`/`report`/`pairwise` print UTF-8 even to a Windows pipe (`ocr_eval.utf8_output()`).
- **CI** (`ocr-eval.yml`, on PRs and pushes to main that touch recognition or `ocr_eval/`): every Tesseract variant against `tesseract.json` and `tesseract-commons.json`, `ppocr:v6-small-wl,v6-tiny-wl` against `ppocr-ci.json`, and `ppocr-app` (models from `scripts/fetch_models.py`, cached) against `ppocr-app-ci.json`; each fails on an exact-match drop of more than 2 points. The models are fetched by `python -m ocr_eval.fetch_models` (cache keyed by its `--pins`), which retries network errors and fails on a missing revision or file, a gated repo or an import error; only a PR may skip the PP-OCR comparison, and only when the Hub stays unreachable (exit 75). A change that moves the numbers updates those files (and their `.md` reports) in the same PR, made on Linux.
- Slow engines run on `run --sample N` (a reproducible stratified subset); `python -m ocr_eval.frames` reads a whole frame per call and `python -m ocr_eval.pairwise` pairs runs of different engines crop by crop (McNemar). Tests: `tests/test_ocr_eval_*.py`; `pyproject.toml` puts the repo root on pytest's path for the package.

### Packaging

- `scoresight.spec` has a single entry script, `src/main.py`; PyInstaller follows its imports, so new modules in `src/` are bundled automatically. Platform modules and the win32 `.pyd` are hidden imports chosen by the platform the spec runs on (it can't cross-compile; `--win`/`--mac_osx` are accepted but not needed).
- Data files come from `DATA_GLOBS` in the spec. `tests/test_packaging.py` scans every `resource_path(...)` call in `src/` and fails if what it loads isn't matched by a glob (folder references list the files they load in `FOLDER_CONTENTS`), and checks the built-in OCR models. Load bundled resources only through `resource_path(...)` (it resolves against `sys._MEIPASS` when frozen and the repo root otherwise).
- `tesserocr` (via `cysignals`) and `cyndilib` import some submodules from compiled code, which PyInstaller can't see; the spec collects them as hidden imports. `onnxruntime` is imported lazily, so it is a hidden import too (pyinstaller-hooks-contrib collects its DLLs; its LICENSE and ThirdPartyNotices are bundled). The PP-OCR model files are in `DATA_GLOBS` (the build fails without `scripts/fetch_models.py`); they and onnxruntime add 66 MB on Windows.

### CI and releases

Workflows: `ci.yml` (lint incl. `compile_ui.py --check`, `update_translations.py --check` and a check for the lapsed `scoresight.live` domain; tests and the end-to-end test from source on Linux/Windows, macOS on main), `build.yml` (PyInstaller builds for Windows, macOS arm64/x86_64 and Linux, the frozen-app smoke test, end-to-end test and boot benchmark (fails above 60 s cold / 20 s warm), the same benchmark of the 0.1.0 release for comparison (`continue-on-error`), the Windows installer (ISCC run directly, so no third-party action sees a secret); release builds sign the Windows app, installer and uninstaller with Azure Artifact Signing (`scripts/ci/sign_windows.ps1`) and sign and notarize the macOS app when their secrets exist; runs on PRs that touch packaging, manually and for release tags) and `release.yml`. Releases are manual: `python scripts/bump_version.py X.Y.Z` (updates `src/version.py` if needed and moves the CHANGELOG's `## [Unreleased]` section to `## [X.Y.Z] - <date>`; a final X.Y.Z also takes over the sections of its betas/rcs; `--dry-run` shows the diff), commit, then push a tag `X.Y.Z` (or `X.Y.Z-beta.N` / `X.Y.Z-rc.N`). The tag-triggered workflow checks the tag against `src/version.py`, builds every platform and creates a **draft** GitHub release from that CHANGELOG section with `SHA256SUMS.txt`.

### Other directories

- `scripts/*.py`: standalone tkinter/OpenCV tools for cropping and annotating OCR training data. They're not part of the app (see `docs/data_annotation.md`). `scripts/ci/` holds the version helper and the smoke test used by the workflows.
- `obs_data/`: the OBS scene collection and images used by "Create OBS Scene".
- `brand/`: the logo, drawn by `scoresight_brand.py`. `python brand/make_assets.py` writes the app icons (`icons/scoresight.ico`, `icons/scoresight-macos.png`), the splash screen, the docs logo, the favicon and the social preview from it. Don't edit those files by hand.
- `docs/`: the user guide (Jekyll site) and `docs/development/`.
